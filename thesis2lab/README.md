# Thesis2Lab

Turn a thesis into an interactive research laboratory that runs in an ordinary web browser. Readers can trace claims to evidence, rerun supported analyses, change parameters, compare with original results and export a reproducibility record. No AI key, server or Python installation is needed to use it.

**Core principle:** use AI to build the laboratory, not to run every visitor interaction.

The first project is *The Legal Last Mile* (sanitation governance and administrative law in Brazil, Ontario and the Netherlands). The thesis is not written yet, so the lab is honest about that: three experiments, each showing the status its evidence supports.

| Experiment | Data | Status |
|---|---|---|
| EXP-001 Bibliometric explorer | synthetic, invented | Exploratory (software demonstration, not a finding) |
| EXP-002 Coding-agreement audit | authentic labels, hashed ids | Partially reproduced (published kappa values recomputed; confidence intervals not) |
| EXP-003 Theme shares, 83,596 decisions | raw data not available | Blocked |

## Quick start
```
npm install
npm run dev          # open http://localhost:5173
npm run build        # validates records, runs experiments against references, builds app/dist
```
Tests: `npm test`, `npm run test:py`, `npm run test:e2e` (after a build). Details: `docs/DEPLOYMENT.md`.

## How it stays honest
- The interface shows a status only if a current validation report supports it. Change the code or data and the report goes stale, and the status drops to Unverified.
- Every calculation exists twice: TypeScript for the site, an independent Python version for verification.
- Reports are generated by running programs, never written by hand. Independent human review stays "pending" until someone signs it.
- Synthetic data is labelled on every screen and can never be Reproducible.

## For other researchers
Nothing project-specific is hardcoded. Replace `project.config.json`, the records in `research/`, and the folders in `experiments/`. See `examples/other-project/` and `docs/ADDING_RESEARCH.md`.

## Layout
`app/` interface and calculation code, `experiments/` one folder per experiment, `research/` thesis, sources, claims, methods, governance evidence, `data/` datasets and JSON Schemas, `validation/` generated reports, `pipelines/` Python ingest, `scripts/` tooling, `docs/` documentation. Read `CLAUDE.md` for the working rules.
