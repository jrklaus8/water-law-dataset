# Reproducibility standard

## Statuses
| Status | Requires |
|---|---|
| REPRODUCIBLE | Current report; all required checks pass; at least one numerical comparison against an **original** reference (original output or published value); methodological fidelity checked; repeatability passes. |
| PARTIAL | Current passing report and at least one original output reproduced, with named unresolved elements. |
| AUDITABLE | Evidence and procedure inspectable; no computation claimed. |
| EXPLORATORY | Independent simulation or demonstration; current passing report for technical correctness. Never a reproduction. |
| BLOCKED | Something required is missing; the manifest says what. |
| UNVERIFIED | Implementation exists without a current supporting report. Also the automatic fallback. |

Synthetic data can never be REPRODUCIBLE (enforced by the schema validator).

## What a report records
Experiment id and version, declared status, `inputs_digest`, git commit and dirty flag, tool versions, dataset checksums, every check with expected, actual, tolerance and difference, a four-part summary (technical execution, numerical agreement, methodological fidelity, repeatability), independent review state, and remaining uncertainty. Generated by `scripts/run-validation.ts` only.

## Rules
- Tolerances are set per metric in the reference file, justified by the rounding of the published value. No universal tolerance.
- References are original (output of the original code), original_published (stated in a document), or independent_reimplementation. Only the first two can support REPRODUCIBLE or PARTIAL.
- Chart similarity is never evidence. Qualitative interpretation is never equivalent to numerical replication.
- A failing non-required check is shown, listed under remaining uncertainty, and keeps the claim from being labelled fully reproduced.
- Independent review is `pending` until a reviewer signs `validation/reviews/EXP-nnn.json` (`{"inputs_digest","reviewer","date","note"}`) against the current `inputs_digest`; a later change voids the signature. Substantive scientific conclusions need human approval.
- Releases are drafts until a researcher sets `approved_by`.
