# Auditing and reviewing this review — a guide for scholars, students, supervisors and critics

This is a large, partly AI-conducted systematic review, and it has been corrected several times while being built. This
guide tells you how to check it rather than take it on trust: where the numbers come from, how to follow a single study
from search hit to synthesis, what has already gone wrong and been fixed, and what is still unverified.

## 1. Start here (15 minutes)

1. **Read the caveats first:** `README.md` → "Known limitations" (16 numbered items). They are the project's own list of
   what it cannot claim. Then `00_admin/DECISIONS_AND_OPEN_ITEMS.md` for what is still undecided.
2. **Check the numbers yourself:** run, from this folder, `python3 code/analysis/verify_repository.py`. It re-derives every
   headline figure from the CSV databases, checks that the databases agree with each other, and checks that the
   current-status documents quote the same figures. `00_admin/CURRENT_FIGURES.md` is the human-readable output. If a document
   ever disagrees with that file, the file is right.
3. **Read the audit trail:** `CHANGELOG.md` (newest entry first, every entry dated) and
   `00_admin/audits/2026-09-28_repository_audit.md` (16 findings, what was wrong, what was fixed, what is open).

## 2. What is human and what is AI

| Stage | Who did it | Independent human check |
|---|---|---|
| Search, deduplication | Researcher (databases, exports) + scripts in `code/search/` | Deduplication audits 2026-09-28 (DOI, title/author) |
| Title/abstract screening | AI first pass; human second reviewer | Yes, all records (99.8% agreement, itself flagged as unusually high — see README) |
| Full-text screening | AI reviewer (`reviewer_1`) | **Only 100 of the included studies (S001–S100) confirmed by a human `reviewer_2`**; excludes not reviewed |
| Extraction (92 fields) | AI | **None yet** — no second-extractor pass |
| Risk-of-bias ratings | AI, rule-based batch process from extracted fields | **None yet**; not a signalling-question read of each paper |
| Synthesis (Phase 11 judgment, SWiM) | AI, from the extracted data | None yet |

Nothing in this repository should be described as independently verified beyond that table.

## 3. Trace one study end to end

Take any `study_id` (e.g. `S294`):

| Step | Where | How to find it |
|---|---|---|
| Source paper's screening record | `02_screening/full_text/full_text_screening_database.csv` | `03_extraction/extracted_data/study_record_map.csv` gives the `record_id` for every `study_id` |
| Title/abstract decision and rationale | `02_screening/title_abstract/screening_database.csv`, `ai_first_pass_rationale.csv` | same `record_id` |
| How the record entered the pool | `01_search/` (search logs, per-database strategies, `merge_log.csv`) | `record_id`, `doi` |
| Extracted data | `03_extraction/extracted_data/extraction_database.csv` | `study_id`; field meanings in `CODEBOOK.md`, `DATA_DICTIONARY.md` |
| Risk-of-bias tool and rating | same row (`risk_of_bias_tool`, `risk_of_bias_rating`); method in `RISK_OF_BIAS.md` §4 and `04_quality/appraisal_forms/` | full per-study forms exist only for the 5 RoB 2 and a few dozen ROBINS-I/AMSTAR 2 studies; the rest are covered by the `*_batch_2026-09-28.md` method notes |
| Classification | `05_analysis/descriptive/evidence_map.csv` | `study_id` |
| Effect size (if any) | `05_analysis/effect_sizes/effect_sizes.csv` | `study_id`; `provenance_note` says where each number came from |
| Where it appears in a synthesis | `06_outputs/supplementary/family_{A,B,C}_swim_synthesis_2026-09-28.md` | `study_id` |
| The script that wrote its rows | `code/provenance/` | `grep -rl "S294" code/provenance/` (coverage starts at `record_batch64` / study S532; earlier work has no surviving script, only `git log`) |
| Everything that ever changed about it | `git log -p -S"S294" -- 03_extraction/` and `CHANGELOG.md` | |

Two things to know: the extraction database has no `record_id` column, so the link is the map file above; and **extraction is
per report, not per underlying study** — companion papers of one study are listed in
`03_extraction/extracted_data/linked_reports_2026-09-28.csv`.

## 4. What has already gone wrong (so you know where to look)

The 2026-09-28 audit found, and this repository corrected in the open, problems of these kinds. Look for their siblings.

- **Hand-typed figures going stale** across documents (tool distribution, screening totals, percentages). Now generated by
  `code/analysis/current_figures.py` and checked by `verify_repository.py`.
- **Two papers counted twice** (language-variant titles, blank DOI), missed by both duplicate audits. Merged; the class of
  error (same paper, different-language titles) is still not detectable by the DOI/title audits.
- **A sign-versus-valence error** in a synthesis (a coefficient's sign summed as if it meant "helps access").
- **Provenance gaps:** 73 decided full-text rows with no recorded reviewer; one abstract-only include resolved on its full
  text (excluded); one effect-size row for a study not flagged eligible.
- **Extractions from abstract or metadata only** (69 studies) — listed in
  `05_analysis/sensitivity/abstract_only_extractions_2026-09-28.csv`; none feeds an effect-size row.

## 5. Ways to challenge a result

- **Re-run a classification:** `code/analysis/current_figures.py` documents the tool-bucketing rule (earliest tool keyword) in
  code; try your own rule and compare.
- **Re-derive a synthesis count:** the SWiM documents give each study's coded direction; `effect_sizes.csv` holds the
  extracted `direction` text. Sign and valence differ for several studies — see the Family A and C documents' notes.
- **Test a sensitivity:** drop the abstract-only studies (file above), the S589 row, or collapse linked reports, and see
  whether any conclusion moves. The synthesis documents state which decisions were judgment calls.
- **Check a rating:** ratings are rule-based from extracted fields (`RISK_OF_BIAS.md` §4). "High concern" on a JBI rating
  usually means sparse extraction, not a poor study. The Legal Institutional Evidence Appraisal Framework is this project's
  own **non-validated** instrument and is labelled as such.
- **Re-screen a sample:** `02_screening/full_text/full_text_reviewer_2_queue.csv` (built by
  `code/screening/build_full_text_reviewer2_queue.py`) lists decided-but-unconfirmed records for a human second reviewer.

## 6. What this review does not claim

No pooled effect exists: Phase 11 found that no synthesis family clears the bar for meta-analysis, and every
`effect_sizes.csv` row has `included_in_pooled_estimate = FALSE`. The three structured (SWiM) syntheses report direction of
association with disclosed judgment calls; they are not effect estimates and not certainty-graded (GRADE) conclusions.
Full-text retrieval was closed by researcher decision with 1,383 records never assessed, so the corpus is not exhaustive.
Source PDFs are not in the repository; the extracted values could not be re-checked against them by the audit.

## 7. Keeping it auditable

- Change data with a small dated script that asserts row counts and writes atomically (pattern in
  `code/provenance/README.md`); put the script under `code/provenance/audit_and_repair/`; add a dated `CHANGELOG.md` entry.
- After any data change run `python3 code/analysis/current_figures.py --write`, update any current-status document the
  verifier flags, then run `python3 code/analysis/verify_repository.py` until it passes.
- Never renumber or reuse a `study_id`; retire it (see the retired IDs listed in `00_admin/CURRENT_FIGURES.md`).
- Do not rewrite dated historical text; add a dated correction beside it.
